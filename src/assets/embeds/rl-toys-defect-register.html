Two patterns, not sixty unrelated bugs

A reset that puts the robot somewhere other than where the code says. The spawn height, the folded legs, the yaw filter's bias, the observation cache. Three of these were found independently by three people at three different times; the fourth is still open. The training path has no gate that asserts where the robot actually starts.

A consumer with no parity-test partner. The observation grew 36 → 40 and the change landed perfectly in the two implementations that have a parity test between them — and missed both consumers that don't. Stage A and Gate V4 are dead as a direct result.

The gates pass because V0–V4 all run through mujoco_backend.py, the standalone parity backend, which is correct. Nearly every finding below is in wlbot_mjlab/tasks/ — the training path — which no gate exercises end to end.

  • LR schedule documentedThe lin_ prefix drop is now stated in the config instead of silently truncated.
  • apply_delay — not a bugmjlab 1.6.0 calls it from the entity, outside compute. Overriding compute without super() does not disable the action delay. Closed.

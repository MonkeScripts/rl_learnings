Station-keeping policy runner

How a trained reinforcement-learning actor gets from a Hugging Face artifact onto the wheels of a self-balancing robot, what stops it when it misbehaves, and what has actually been measured.

1

What runs, and where

The control tick owns the robot. It runs at 500 Hz on core 1 and never waits for the policy. Every fifth tick it posts a sensor snapshot to a mailbox and moves on. The policy task sits one priority notch below it, so by construction it executes only in the gaps the tick leaves and can never delay balancing.

The dashed edge is the loop's only feedback. The action the network produced goes back into the next observation, before any scaling, ramping or capping the firmware applies. Feeding back the volts instead would put the firmware's own limiters inside the network's idea of what it just did.

Two constants here are pinned to what training believed rather than to what the robot measures. Odometry uses a nominal wheel radius of 0.019205 m, and the 10 ms step is baked into the assembler's filters. Re-measuring the wheel must not silently move the policy's sense of distance, and the rate is not a free parameter: the four-frame stack spans three of those intervals, so the network learned what one frame ago means in seconds.

Two actions come out. The first becomes the common voltage on both wheels at a scale of 8 V, the second the differential yaw voltage at 4 V.

3

The network on the chip

A 40 → 64 → 64 → 2 tanh network, quantized to int16 by esp-ppq and executed by esp-dl. Both tanh layers became 2049-entry lookup tables during quantization, which is where most of the arithmetic saving comes from: on the float path those were 128 calls into tanhf, and they cost more than the 6,784 multiply-accumulates did.

Inside the graph

Three matrix layers, two tanh lookups, and a final clip to the unit interval. w16a16: 16-bit weights, 16-bit activations.

Deliberately outside it

The per-channel normalisation, the multiplication to volts, and the guard against a non-finite action. Each is in C, and each for a reason worth keeping.

The normalisation stays out because folding it into the first layer would hand the quantizer forty channels whose raw ranges span three orders of magnitude, all sharing one 16-bit scale. Normalising first puts every channel near unit scale, which is why training normalises there too.

The guard against a non-finite action stays out because ONNX carries the clip but not the float path's check for a value that is not a number. This is the last place before an action becomes voltage, so the wrapper refuses to publish one.

The calibration range decides which observations the graph can represent. The input range is chosen from observations shown to the quantizer, and anything outside it is clipped at inference time, which is a far larger error than rounding.

On 2026-09-09 a step cap fed the calibrator the first ten seconds of a ninety second run. It sized the range to ±0.25 for a run that reaches 0.695, and 4.8% of rows then had a channel clipped, the action feedback and the gyro among them. On those rows the quantized network disagreed with the float one by up to 7 V of motor command, and the robot flew visibly worse.

Calibration now spreads across the whole window with the largest-magnitude rows forced in, uses a minmax range rather than the default KL, and the exporter prints the count of rows that fall outside the chosen range. That count must be zero.

4

Taking the wheels, and losing them

An operator asks for the handover, and the request is a flag applied against live inputs on the next tick, because the request itself can be a hundred milliseconds stale by the time it arrives. Releasing is unconditional and always allowed.

Every reason a handover is refused or revoked. Grant-only checks run once; continuous checks run every tick at 500 Hz and eject mid-flight.
RefusalWhenWhy it exists
DISARMEDgrantTraining episodes start balanced with wheels down
REFLEXgrant continuousThe crouch reflex runs off tilt whoever holds the wheels, and a crouch below the trained height would eject the policy mid-disturbance
HOMEgrant continuousThe homing cascade banks owed travel while the policy drives and would repay all of it the instant the PD law got the wheels back
YAWgrantHeading error is an observation channel, and an unsettled estimator drifts underneath it
DISTURBEDgrantEpisodes start calm
HEIGHTgrant continuousNo height channel and no gain schedule, so the trained 45 to 85 mm band is enforced every tick
STALEgrant continuousOutput older than 60 ms is presumed a dead feed

Two things soften the moment of handover. A 500 ms ramp scales the policy's voltage in from zero, and a hard cap of 6 V bounds it whatever the network asks for. The observation assembler is reset at the grant, which is what makes it a fresh episode with references latched where the robot currently stands.

There is no fallback network any more. The float path was removed from the chip, which returned about 27 KB of DRAM. If the graph refuses to produce a finite action, the runner publishes nothing, the staleness gate fires on the next tick, and the PD law takes the wheels.

That is the same gate a dead feed trips, so the two look alike from outside. The espdl_fb counter in the console info report is what separates them, and it should read zero.

5

What actually checks it

Four gates. Each compares against something the previous one could not reach.

01
ONNX replay This repository reads a published graph the same way onnxruntime executes it, to 1e-5 over 512 observations. It exists because a graph can be read wrong in a way that is self-consistent everywhere afterwards: a published actor's square 64×64 layer arrived untransposed, everything downstream agreed with itself, and the network was 1.27 out on the action. just export-policy
02
Golden replay The generated C assembler and the float reference network, compiled with host gcc, replayed against the numpy twin over 240 chained steps. Holds to 2e-4 on the action and 1e-3 on volts, and currently passes at 3.3e-7. scripts/test_policy.py
03
Quantization grading The int16 graph against the float network across an entire real capture, reported split by whether any input channel fell outside the quantized range. An earlier version graded only a held-out tail, which happened to be the quietest stretch of the run, and reported 1.16e-3 for a network that was 0.87 out where it mattered. just export-espdl
04
On-device vectors Thirty-two observations baked into the firmware, graded on the ESP32 itself against esp-ppq's bit-exact integer twin of esp-dl's kernels at 2e-4, and against the float network at 6.7e-3. This is the only check that reaches the chip's own arithmetic, and it replaced what was lost when the float network came off. console V

The float weights are still generated into the repository, fenced behind a compile flag that only the host gate defines. They are the oracle. Every accuracy figure quoted about the int16 graph is measured against them, and the clipping failure above was found because they were there to disagree with.

6

Measured timing

Every inference records what it cost, and that column is wall time, not processor time. The policy task sits below the control tick, so a tick landing mid-inference is counted inside the window. The median therefore describes the pipeline delay; the minimum over a long run is the closest available bound on the compute itself.

The gap between 1,364 and 435 is roughly 930 µs that is not arithmetic. The profiler runs its passes back to back with the code resident; a real inference runs once per 10 ms while the tick, the motor commutation and the radio all execute their own code through a 32 KB instruction cache. Everything on the inference path lives in flash, spread across about a megabyte of it. That attribution is inferred from the gap, not measured directly.

Open item: the int16 path has not been profiled. Every figure in the table above is the float network, measured before it was replaced. The quantized network is expected to be quicker, chiefly because the tanh calls became table lookups, but no measurement has been taken on the chip.

The console profiler now times what actually runs: observation assembly, the forty divides, and the graph. Until that has been run, any claim about what the change bought is a prediction.

7

Recording a run

Captures go over the serial cable at 921600 baud, never over the radio. The link drops packets under load and a replay that must reproduce every 100 Hz action row for row cannot tolerate a missing one. The policy task appends an 80-byte row to a small RAM ring and a low-priority task on the other core drains it as text, so the inference path never waits on a UART.

The ring is slack for the drainer, not a buffer you fill and read back. There is nothing to dump and no moment to hit: start the stream, do the run, stop it. If the drainer falls behind, the loss is announced on the stream and counted by the host.

Each row is the complete interface at one inference. The sensor snapshot the runner assembled, the assembler's three derived channels so the training side can check its own arithmetic against ours, the pre-scaling action, and the flags. Four columns exist purely so a capture can be read without outside context, each added because its absence produced a question the first time a file went out.

8

Known limits

·
Station keeping only The two command channels are hardwired to zero, which is the trained distribution. Driving under the policy is two lines in the runner and nothing else, but it is not what this network was trained to do.
·
The rate is not a knob Running faster is a retrain, not a configuration change. The step is baked into the assembler's filters and the four-frame stack, so the same weights at 200 Hz would see references drifting at half the intended rate over half the intended history.
·
Already at the fast edge of training The actor trained with an action delay drawn from 5 to 30 ms. Measured delay on the robot is 6 to 9. Making inference faster moves further off that distribution rather than toward its middle.
·
Zero-order held at 100 Hz When the policy owns the wheels there is no fast inner loop beneath it. Its output is held for all five ticks until the next inference, so it really is a 100 Hz balance controller. If sharp disturbances ever become the failure mode rather than steady station keeping, rate is a reasonable thing to suspect.
·
One published actor has an ONNX The import path takes ONNX and needs no torch, but only one of the seven published runs offers one today. The rest still need the heavier toolchain.

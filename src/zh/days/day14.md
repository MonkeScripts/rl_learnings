## 接着上回

四个接口部件，每个都是有正当理由才加进来的。第 13 天停在一个推翻了我们读法的数字上：单独删掉帧堆叠，存活率掉 0.043；把它和另外三个一起删，只掉 0.007。单项删除量到的是交互效应，不是部件本身。那么，怎样做消融，结论才站得住？

消融（ablation）这个词来自外科和神经科学：切掉一块，看什么不工作了。深度强化学习把它借了过来，然后发现它多么容易骗人。2018 年，Peter Henderson 等人把同一个算法在同一个任务上跑了十个随机种子，分成两组各五个，得到的两条学习曲线差得足以冒充两个不同的算法。2021 年，Rishabh Agarwal 等人回头检查已发表的基准结果：大多数论文只跑得起三到五次，一个点估计里藏着太多不确定性，有些号称的提升，一画出区间就没了。第 10 天那句 Schulman 的话更短：先搞清楚你的噪声。

这些都拦不住人从同一个地方起步。他们的第一次尝试是最直白的那种，我的也是。

## 打个比方

假设一锅汤你调了好几个月，想知道每样调料各起什么作用：盐、酱油、一块浓汤宝、一勺味噌。最直白的办法是再煮四次，每次少放一样，尝一尝。

少放盐，淡了，所以盐重要。少放味噌，也淡了，所以味噌也重要。现在四样全不放，只撒一小撮盐，味道几乎和原来一样。原来这四样干的是同一件事，每一样之所以“少不了”，只是因为别的几样早就为它让出了位置。更糟的是，同一碗汤尝三次，你打的分也不一样。少放一样，测的是这锅汤，不是那样调料；而尝汤的人自己也在晃。第一个问题就出在调料上：单项删除，到底量到了什么？

## 一步一步来

### 一次删一个

轮足机器人的策略看到 40 个输入：十个通道堆四帧，轮子里程计上有一个 50 ms 的低通，航向则由一个航向估计器融合出来，它有十个常数、一个 PI 回路、一个打滑门和一个稳定时钟。训练时，回传的 prev_action 上还加了噪声当正则。同一台机器人的另一套固件，只用六个输入、一个动作就能站稳。担心就是从这个对比来的：这么多复杂度，值不值？

于是做最直白的实验。配方不动（1024 个环境 × 128 步，5000 次迭代，γ = 0.999），每组删一个部件，训练，然后在同样的 3000 个回合上评估，全域随机化，评估种子 12345，再拿每组和 control 比。

| 实验组（删掉了什么） | 存活率 | 晃动 sd | 读法 |
|---|---|---|---|
| control（什么都没删） | 0.976 | 1.58° | 参照组 |
| nolpf（低通） | 0.979 | 2.46°（+56%） | 留着滤波器：没了它更抖 |
| gyroyaw（航向估计器） | 0.973 | 1.99° | 可以删？ |
| noreg（prev_action 噪声） | 0.970 | 1.46° | 可以删？ |
| h1（4 帧 → 1 帧） | 0.911 | 1.54° | 留着帧堆叠：差得最多 |

读起来很干净：留低通，留帧堆叠，另外两个考虑删掉。每条结论都是关于一个部件的一句笃定的话。

可是这几组没有一组真的在问一个部件的问题。这四样是一起调出来的。帧堆叠的深度，是在滤波器已经在的情况下选的；噪声大小，是按四帧历史定的。删掉一个，问的是“这个具体设计没了 X 会怎样”，答案取决于另外三个原本在怎样替它兜底。如果两个部件功能重叠，各自的单项删除看起来是贵是便宜，就看它的搭档能不能接手；单靠单项组，分不出是哪种情况。

::: field 实战笔记：每组只改一处
**什么时候要：** 永远。一个实验组只改一样东西，或者明确写出它改了哪一组东西。**会出什么错：** 提交 `f94036f` 一次就去掉了动作混合器（mixer），又把网络加宽到 128×128，之后没有任何一次 run 把这两件事分开。那几次 run 的每一条读法，都把功劳同时记给两个原因。**怎么测：** 开跑之前，把这一组写成相对 control 的 diff。如果 diff 里有两行都能解释结果，那就是两组。
:::

所以单项组需要一个搭档：一组把这些部件一起删掉，看它们的效应加不加得起来。

### 联合组

没人想跑的那一组，是四样全删：一帧、不滤波、不要估计器、不加 prev_action 噪声。十个输入，接近那套固件的六个。如果效应能相加，光删帧堆叠就已经掉了 0.065，这一组至少该一样差。

结果是 0.970。晃动 1.23°，比 control 还稳。

联合组和单项组对不上的时候，这个对不上本身就是结果。把最要紧的两个部件摆成一个方格：

|  | **低通开** | **低通关** |
|---|---|---|
| **4 帧** | control 0.976（3 个新样本 + 一份深远过去的摘要） | nolpf 0.979（4 个新样本，窗口之外什么都没有） |
| **1 帧** | h1 0.911（只有摘要，没有新样本） | combo 0.970（1 个新样本，没有记忆） |

从 control 往任一方向走一步，都还活得下去；沿左边一列往下走，不行；斜着走，几乎回到原地。机理在第 13 天：一阶滤波器是一个记忆压缩器，四帧滤过的数据，等于三个原始样本加上一份对全部历史的指数加权摘要。只剩一帧时，滤过的通道几乎全是历史，关于“现在”什么也没说，所以 h1 是整张表里最差的一组。帧堆叠的“效应”，其实是“只留摘要、没有新样本”的效应。

这个方格可以算出一个数。分别在滤波器开和关的时候，算删掉帧堆叠的效应，再相减：

$$
I = \big(y_{\text{combo}} - y_{\text{nolpf}}\big) - \big(y_{\text{h1}} - y_{\text{control}}\big) = (-0.009) - (-0.065) = +0.056
$$

::: tip
$I$ 是“删帧堆叠的效应”随“滤波器在不在”变了多少。$I = 0$ 时部件可以相加，单项组就够了。这里帧堆叠在有滤波器时值 0.065，没有滤波器时只值 0.009，所以单项删除的那个数，大半是交互效应。老实说一句：combo 那一格还顺带删了估计器和噪声，它们单独删分别掉 0.003 和 0.006，所以这不是一个完全干净的 2×2。
:::

这就是交互效应（interaction），而联合组是看到它的唯一办法。对不上之后，下一步是跑那一组能把候选机理分开的实验；我的笔记里说，我们只跑了一次，就把问题定了。

**什么时候跑：** 只要这些部件是一起调出来的，也就是永远。**什么时候可以省：** 永远不能省，它只多一次 run。**省掉的代价：** 单项组说留低通、留帧堆叠，两条说的都是交互效应。没有联合组，我们会带着错误的理由记下两条笃定的结论，也永远找不到那个能解释四个格子的记忆论证。**要核对的数：** 我的 Insights 页面写单删帧堆叠是 0.043；种子 0 的表里，h1 比 control 低 0.065。我还没找到 0.043 出自哪一次评估。方向和结论两边都一样。

不过整个方格的读法，都押在一句话上：combo 的 0.970“几乎回到原地”。它比 control 低 0.006。0.006 到底算差别，还是什么都不算？

### 多小才算“没差别”？先量评估器

最直白的回答是评估器是固定的：同样 3000 个回合、同一个种子 12345，所以两个数之间的任何差别，都是两个策略之间的差别。我一直这么信，直到我们把同一个检查点在同一个种子下评估了三次，得到 0.974、0.976 和 0.982。

评估器自己就会动 0.008。所以阈值要由评估器来定，而不是凭直觉：同一个检查点、同一个种子、跑三次，散布多大，平局带就多宽。我们定在大约 0.011，比这小的差别，单个种子分不出来。combo 的 0.006 就在里面。

这个散布有一部分只是计数。存活率是 $n$ 个回合里的一个比例，比例有它的标准误（standard error）：

$$
\mathrm{SE}(\hat p) = \sqrt{\frac{\hat p\,(1-\hat p)}{n}}
$$

::: tip
在 $n$ 个回合上量到的存活率 $\hat p$，换一批回合会挪多少。$\hat p = 0.976$、$n = 3000$ 时是 0.0028；$\hat p \approx 0.93$、$n = 1000$ 时约 0.008，就是我 Wobble Chase 笔记里那个数。回合数翻四倍，它才减半。
:::

三次重复评估的标准差大约是 0.004，比 $n = 3000$ 时光靠计数预测的要大，所以评估器里还有别的东西在每次之间变。我猜是 GPU 物理计算的不确定性，但没测过；要紧的是这个数，而它是量出来的。

同一条规则也决定了哪些指标能用。凭直觉定的平局带，放在航向 RMSE 上会窄得离谱：control 自己的几个检查点之间，它就从 0.212 散到 0.262，和我们想找的任何效应一样大。所以航向 RMSE 被从判据里拿掉了。

::: field 实战笔记：让评估器来定阈值
**怎么测：** 同一个检查点、同一个种子、评估三次。阈值 = 这个散布。我们的是 0.974 / 0.976 / 0.982，所以单个种子下约 0.011 以内的差别分不出来。**会出什么错：** 每格回合太少。默认的晃动探针每格只跑 4 个回合，它让 sk_lean5 的 model_9500 看起来像是“训练越久策略越平滑”的证据；每格跑到 12 个回合，那只是散布。❌ 没有量过散布的探针，是故事，不是测量。
:::

噪声底量出来了，单个种子下 combo 在它里面。可这个噪声底，只是评估一个 run 的一个检查点时的噪声。run 本身也是抽出来的：换一个训练种子，就是另一个策略。

### 种子和检查点也是噪声

“0.006 是不是真的”最省事的办法，是换新种子把这两组再训一遍。每组三个种子：

| Run | 种子 0 | 种子 1 | 种子 2 | 均值 | 36-44 ms 档，均值 |
|---|---|---|---|---|---|
| control | 0.976 | 0.975 | 0.973 | 0.975 | 0.923 |
| combo | 0.970 | 0.964 | 0.971 | 0.968 | 0.905 |

control 最差的种子 0.973，高于 combo 最好的 0.971。各一个种子时，0.006 的差距淹在噪声里；三个种子时就不是了，长延迟档拉得更开。把上面的浏览器切到“3 个种子”就能看到这几个点。所以 combo 确实差一点：均值差大约 0.007。

种子还不是唯一的抽样。在一个 run 内部，训练后期是随机游走（第 11 天）：相隔 100 到 500 次迭代的检查点，晃动差 6°，航向角速度 RMSE 差 0.3。sk_lean5_s2 从 5000 到 9999 的六个检查点，在 $n = 1000$ 下存活率落在 0.929 到 0.955 之间，而一次读数的标准误就有 0.008 左右：这六个是同一个策略的六次抽样。两个 run 之间的比较，如果各自只靠一个检查点，比的就是两次抽签。

抽签还得在同样的条件下抽。一个 20,000 次迭代的 run，到第 5000 次时推力还只有一半，所以它在 5000 时的存活率，不能和一个 5000 次迭代的 run 在 5000 时的存活率比。迭代对齐、推力对齐，否则不比。

::: field 实战笔记：检查点对齐，否则不排名
**什么时候要：** 比较任意两个 run 时。在相同迭代、相同课程阶段比较，并且看好几个检查点，不只一个。**会出什么错：** 在 mjlab 关卡上，sk_lean5 的 model_5000 赢了 sk_lean3 的 model_4999，0.948 对 0.927，配方和种子都一样。但这只是一对 run、各一个检查点，后来台架更喜欢 sk_lean3。**差别是真的证据：** 三个种子里，一组最差的胜过另一组最好的。⚖️ 三个种子要多跑三次；我们只给打算据此行动的组付这个钱。
:::

扯远了，我们先回顾一下。一开始一次删一个，得到四条笃定的结论。联合组表明，它们读到的是交互效应。评估器自己的散布告诉我们，单个种子下 combo 的 0.006 看不见；三个种子让它看见了：combo 确实差大约 0.007。剩下的问题，存活率这一列回答不了：0.007 的存活率摊在 3000 个回合上，说不出丢掉的机器人倒在哪里，也说不出这对台架上的机器人重不重要。

### 均值藏住了尾巴

头条指标是对随机化抽到的每个回合取平均，而大多数抽样都不难。动作延迟每个回合在 5 到 45 ms 之间抽一次。第 13 天讲过难点在哪：辨识延迟要好几对（动作，响应），接口一削弱，留下的对数就少了。所以接口被削弱之后，策略就像一个按平均延迟调的策略，而平均值在尾部是错的。

损失就落在那里。在种子 0 的表上，36-44 ms 档（最长持续延迟的那四分之一）对每个被削弱的组都比存活率掉得多：h1 掉到 0.757，nolpf_jerk1 掉到 0.891，combo 掉到 0.912，而 control 是 0.936。这一档还做到了头条指标从没做到的事：它预言了台架。combo（三个种子 0.905）和 jerk 惩罚组（0.891）被推一下之后，都要往前冲得更远才救回来，而 control 是 0.923。长延迟档已经三次在我们看到之前说中了台架上的表现。

所以规则是：找到能预言你硬件的那个指标，按它来做决定，而不是按头条指标。一个好的起点，是你随机化的那个量的尾部分档。Schulman 的清单讲的是同一件事的一般版：看最小值、最大值和回合长度，不要只看均值。

但一个指标要靠预言准来挣到这份权重，而不是靠看起来相关。仿真里的晃动探针，看上去是我们手里最相关的数，毕竟台架上抱怨的就是晃。它两个方向都错了。model_5500 在仿真里很稳，到了机器人上晃；21 个检查点的权重平均是我们量过最稳的策略，把仿真晃动减半，到了台架上却输给了 model_4500。我未经验证的猜测是：在仿真里看起来稳的策略，修正动作都很小，到了硬件上就被齿隙、静摩擦和柔性吃掉了。不管原因是什么，探针的记录是两次失手，延迟档是三次命中。

::: field 实战笔记：知道仿真定不了什么
**规则：** 时间常数比回合还长的部件，不管建模多忠实，都没法用回合来评估。**证据：** 航向估计器的稳定时钟是 20 s，回合是 10 s，所以仿真在重置时直接把它瞬移到已稳定状态，我们造它要解决的那部分从来没被测过。⚖️ gyroyaw（0.973）读起来可以删，但只有一个种子。这是硬件的问题，不是再跑一个种子的问题。
:::

延迟档三次命中，探针两次失手，而哪个是哪个，我们是看了台架之后才知道的。九个组、六七个指标，事后总会有某个指标和发生的事对得上。唯一的防线，是在跑之前先说出我们预期什么。

### 先把预测和终止规则写下来

sim2sim2real 这个实验，我从一开始就是这么跑的。论文（arXiv 2606.02636v2）提议：先在理想化的仿真器里学行为，冻结一个机器人运动学的前向模型，再在随机化的对象上用模仿奖励重新训练。对照组是 sk_lag_r128_s0：在真实对象上，最后一个检查点存活率 0.870，4500 时是 0.886。每次开跑之前，预测和终止规则（kill rule）都先写进日志，一个调度器按这些规则、读训练日志自己的标量来终止阶段。

| 开跑前写下的预测 | 结果 |
|---|---|
| 第一轮：B1 在 5000 时不低于 control | 1000 时被终止：没中 |
| 第二轮：A2 在干净评估上 ≥ 0.9，过关卡 | 0.975：证实 |
| 第二轮：B1 在 5000 时与 control 相差 0.02 以内，不指望超过 | +0.014，全部打平：证实 |
| 第二轮：B1 − B0 ≥ 0.02 才算模仿项有用 | +0.010 和 −0.003：无效 |
| 第二轮：校准后的核能救回第一轮的模型 | 1000 时被终止：没中 |
| B1S：与 control 打平 | 3000 时 0.832 对 0.877：低于 control |

这张表里有两件事，只因为每一行是先写的才存在。“无效”是一个结果：B1 和 B0 只差模仿项，而“有用”的门槛 0.02 是在两者开跑之前就定死的，所以 +0.010 事后没法被吹大。没中的就记成没中，不会被悄悄改读成“迭代还不够”。

纪律的另一半，是在训练之前先做一次检查。第一轮失败后，我们直接给冻结的模型打分：在对象上跑一个已知好用的控制器，每一步都像奖励那样套上模仿核。第 12 天那个 7.5σ 的核就是这样被发现的。几分钟就找出了两个毛病（对象里没有延迟，核窄到够不着），省下了又一次五小时的训练。

第 10 天的 run doctor 对单次训练做的是同一件事：sk_lean4 事先写下的 0.87，结果是 0.65，`prediction_missed` 老老实实把它记成了没中。

::: field 实战笔记：预先登记，终止规则盯对数
**什么时候要：** 每一次你打算据此行动的开跑之前。写下预测、平局带和终止规则。**会出什么错：** sk_lean5_s0 的终止警报盯的是奖励，而某个奖励权重一打开，奖励按构造就会掉；警报响的时候，回合长度正在涨。它的同胞 sk_lean5_s2 把这个形状摆得很清楚：第 500 次迭代航向项打开时，reward per step 从 0.65 掉到 0.49，回合长度却一路往上（841、857、889）。终止规则要盯一个不会按设计变动的数。**怎么测：** 训练之前，先拿一个已知好用的控制器给冻结的模型打分。✅ 几分钟就抓到了 sim2sim2real 的两个毛病。
:::

::: field 值得记住的弯路
- 两个改动进了同一个提交（逐轮动作和 128×128），之后没有任何 run 把它们分开。
- 拿迭代数不同、推力不同的 run 互相比较。
- sk_lean4 只看训练奖励，四天都没过关卡。
- 终止警报盯着奖励，而权重一打开，奖励按设计就会掉。
- 一个 4 回合的晃动探针，让 model_9500 看起来像“训练越久越平滑”的证据。
- “逐轮动作学航向要多花一倍时间”，这个结论只凭 sk_lean4 得出，一小时后就被 sk_lean4b 和 4c 推翻了。
:::

预先登记定下了我们预期什么，噪声底定下了我们分得清什么。还缺的，是一个说明我们有多确定的数。“最差的种子胜过最好的种子”是用眼睛看出来的。三个种子，它到底能说明多少？

### 统计小入门：多确定才算确定

这一页上的每个数都是一次抽样，而抽样要的是区间，不是一个点。像我们这样的消融，三样工具就够，而且值得都用在同样六个数上：control 0.976 / 0.975 / 0.973，对 combo 0.970 / 0.964 / 0.971。

**单次评估的置信区间（confidence interval）。** 第 3 拍的标准误直接给出：如果计数是唯一的噪声，$\hat p \pm 1.96\,\mathrm{SE}$ 大约 95% 的时候罩得住真实存活率。control 在 $n = 3000$ 时是 0.976 ± 0.0055。我们量到的评估器散布说明，真实的区间还要宽一点。

**对种子做自助法（bootstrap）。** 有放回地重抽种子：从三个 control 种子里抽三个（可以重复），从三个 combo 种子里抽三个，算均值之差。把所有可能的抽法都做一遍，三个种子时一共只有 $27 \times 27 = 729$ 对，再看它们散得多开。我算出差距 0.006，95% 百分位区间 0.003 到 0.010，729 次重抽里没有一次落在零或以下。问题在于：自助法只能重新洗它见过的散布，而三个种子见过的不多。三个种子时，它偏乐观。

**一个排序论证。** 如果 control 和 combo 其实一样，把六个数分成两组各三个，每一种分法的可能性都相同。分法一共有

$$
\binom{6}{3} = 20
$$

种，只有一种让三个 control 种子全部高于三个 combo 种子。

::: tip
如果两组其实一样，“最差胜过最好”在各三个种子时，大约 20 次里会碰巧出现 1 次（单侧）。这是三对三能说出的最强的话。在同样的数上做一个普通的 t 区间，它依赖一个三个点根本检查不了的正态形状，结果刚好把零包进去。
:::

所以三个种子说的是“大概是真的，碰巧的机会约二十分之一”。让我真正相信的，是长延迟档也同意，然后台架也同意。Agarwal 等人给基准测试推荐的也是这些习惯：报告区间而不是点估计，用四分位均值（IQM）代替少数几次 run 的均值或中位数，看分数的整个分布。只有一台机器人、一个任务时，能带走的是第一条。这里的区间、自助法和二十分之一，都是我在日志数值上自己算的，不是项目里报告的结果。

::: field 实战笔记：光有好分数，什么也说明不了
**在别处怎么咬人：** 拟合 HD-1910 舵机模型。没设种子的并行 CMA-ES，在一个平坦、带黏滑摩擦的地形上，每次都落在不同的地方；两次几乎相同数据上的拟合，力矩常数一个是 0.47、一个是 0.91，误差却几乎一样。**怎么测：** 同一个拟合跑两次。分数一样、某个数却不一样，说明数据定不了这个数。用拟合从没见过的数据来验证：Kp 8 的日志和负载 D 都是留出来的。✅ 和“三个种子”是同一条规则，只是用在系统辨识上。
:::

现在我们能说自己有多确定了，不过说的是一台机器人、在一个仿真器里。这一页上的每个区间、每个种子、每个检查点，都是同一个引擎打的分；而区间不会告诉你，这个引擎给策略排的名次，和机器人排的是不是一样。

## 常见坑

- **一组里改了两处（第 1 拍）。** 这次 run 看起来像个结果，其实是两个假设。等到有人问“到底是哪个改动起的作用”，没有哪次 run 答得上来，你才会发现。
- **只有单项组，没有联合组（第 2 拍）。** 症状是一串“缺一不可”的部件，加起来比整个设计能损失的还多。如果一起删两个比单删任何一个损失都小，单项组量到的就是交互效应。
- **凭直觉定平局带，或者探针小到根本没法有平局带（第 3 拍）。** 4 回合的探针，或者单种子下小于 0.011 的差别，往哪边都能编出一个笃定的故事。先量重复散布。
- **不对齐的比较（第 4 拍）。** 在不同迭代、不同推力下比两个 run，或者不过关卡、只看训练奖励。sk_lean4 的训练奖励看起来像是学得慢；关卡一过，原来是一台在原地打转的机器人。
- **终止规则盯着一个会按设计变动的数（第 6 拍）。** 课程里的权重一打开，reward per step 就会掉。把规则挂在回合长度或关卡上；预测没中，先记下来，再决定是不是节奏问题。
